# 분석 결과를 덮어쓰기 전에 확인하는 법 — 계획

2026-08-27 · LEP `2.25.0` 기준 · **계획서. 아직 아무것도 안 고쳤다.**

기존 데이터는 그대로 둔다. 이 문서는 **앞으로 도는 분석**에 적용할 안전장치를 정한다.

---

## 0. 무엇이 문제인가

오늘 하루에만 다섯 건이 났고, **다섯 건의 공통점이 하나다.**

> **분석 결과가 명백히 잘못돼도 그대로 덮어쓴다. 아무도 안 막는다.**

| # | 무슨 일이 났나 | 무엇이 막았어야 했나 |
|---|---|---|
| 1 | `recordingIds` 없이 재분석 → 멀쩡한 결과가 「분석된 녹음이 없습니다」 로 덮임 | **전사문이 비었는데 기존에 있었다** — 그러면 덮으면 안 된다 |
| 2 | 전사 1027줄을 지우고 한 줄씩 5분간 다시 넣음 → 그 사이 화면이 부분 상태 | 한 트랜잭션이어야 한다 |
| 3 | 역할 판정이 **45명 중 0명** → `미상 8818단어` 가 그대로 저장 | 전부 미상이면 **이상하다고 적어야** 한다 |
| 4 | 화자 45명이 그대로 저장 → 화면에 45장 | 화자 수가 터무니없으면 남겨야 한다 |
| 5 | 26명 넘으면 이름이 `화자 ]`·`화자 `` 로 깨진 채 저장 | 이름에 기호가 들어가면 안 된다 |

1번은 **내가 냈다.** 인자 하나 빠뜨린 것으로 사용자의 분석이 사라졌다.
전사 원문이 남아 있어 복구했지만, **원문까지 지우는 경로였다면 되돌릴 수 없었다.**

3·4·5는 아무도 몰랐다. 사용자가 화면을 보고 「말이 안 된다」 고 알려 줘서 알았다.

---

## 1. 원칙

**① 덮어쓰기 전에, 새 결과가 옛 결과보다 나쁘지 않은지 본다.**
분석은 「다시 돌리면 좋아진다」 가 아니다. 모델도 STT 도 매번 다르게 나온다.

**② 나쁘면 안 덮고, 왜 안 덮었는지 남긴다.**
조용히 거부하면 「분석이 안 도네」 가 된다. 거부한 이유가 화면에 보여야 한다.

**③ 이상하지만 나쁘다고 단정할 수 없는 것은 덮되, 적어 둔다.**
화자 45명은 틀린 값이 아니라 **틀린 것처럼 보이는 값**이다. 막으면 진짜 45명인 회의를 막는다.

**④ 되돌릴 수 있게 한다.**
게이트를 아무리 잘 짜도 새는 것이 있다. 이전 판이 남아 있으면 사고가 사고로 안 끝난다.

**⑤ 파괴적인 것을 기본값으로 두지 않는다.**
인자를 빠뜨렸을 때 **가장 조용히 망가지는 쪽**으로 가면 안 된다.

## 2. 계획

### A. 쓰기 직전 게이트 (`services/analysisGate.ts` · 신규)

분석 결과를 저장하기 **직전**에 한 번 통과시킨다. 판정은 셋뿐이다.

```
BLOCK   덮지 않는다. 옛 결과가 남는다. 이유를 analysis_note 에 적는다
WARN    덮되, 무엇이 이상한지 analysis_note 에 적는다
OK      그냥 덮는다
```

**BLOCK 조건** — 「이건 결과가 아니다」 인 것만. 좁게 잡는다.

| 조건 | 왜 |
|---|---|
| 새 전사문이 비었는데 **기존에는 있었다** | 사고 1. 되돌릴 수 없는 손실이다 |
| 새 세그먼트가 0개인데 기존이 100개 이상 | 같은 이유 |
| 새 세그먼트 수가 기존의 **50% 미만** | 전사가 반쯤 실패한 것 |
| `summary` 가 우리가 만든 **경고 문구**다 (`⚠️` 로 시작) | 그건 결과가 아니라 실패 안내다 |

**WARN 조건** — 「이상하지만 맞을 수도 있다」.

| 조건 | 적을 말 |
|---|---|
| 화자 수 > 12 | 구간을 못 이었을 수 있다 · 실제 인원이 아닐 수 있다 |
| 역할이 **전부 미상** | 역할 판정이 하나도 안 됐다 |
| 구간이 2개 이상인데 연결 0건 | 겹침이 없어 못 이었다 *(이미 있음 — 게이트로 옮긴다)* |
| 화자 이름에 영문·한글이 아닌 글자 | 이름 만드는 코드가 깨졌다 *(사고 5)* |
| `talkRatio` 합이 0.9 미만 | 어디로 샜는지 알 수 없다 |

**게이트는 순수 함수로 만든다.** DB 도 모델도 안 부른다 —
`(옛 결과 요약, 새 결과) → 판정`. 그래야 결함을 심어 시험할 수 있다.

### B. 원자적 교체

전사 세그먼트는 지금 `delete` 뒤에 **한 줄씩 1027번** 넣는다. 트랜잭션도 없다.

- `begin` … `commit` 으로 묶는다. 실패하면 옛것이 그대로 남는다
- **묶음 삽입** — 200줄씩 한 문장으로. (열 8개 × 200 = 1600 파라미터, 상한 65535 안쪽)
- 재분석 시간이 5분대에서 크게 줄어든다 (지금 대부분이 왕복 시간이다)

> 오늘 이 문제로 사용자가 **차오르는 전사**(739 → 936 → 1027)를 보고 있었다.

### C. 이전 판을 남긴다 (`030_analysis_history.sql`)

```sql
create table v2.analysis_history (
  id uuid primary key default gen_random_uuid(),
  meeting_id uuid not null references v2.meetings(id) on delete cascade,
  result jsonb not null,          -- 덮이기 직전의 analysis_results 한 행
  segment_count int,
  replaced_at timestamptz not null default now(),
  replaced_by text                -- 누가·무엇이 덮었나
);
```

- **덮기 직전에 한 줄 넣는다.** 크지 않다 — 미팅당 분석은 몇 번 안 돈다
- 오래된 것은 미팅당 최근 5개만 남긴다
- 되돌리는 것은 **사람이 고른다.** 자동 복구를 만들지 않는다
  (「자동으로 지우는 청소기를 만들지 않는다」 와 같은 규칙)

### D. 파괴적 기본값 없애기 *(이미 함 — 2.25.0)*

`recordingIds` 가 없으면 이미 붙어 있는 녹음을 쓴다. `metadata` 는 녹음이 정말 없을 때만.
**남은 것**: `source: 'metadata'` 를 아예 명시적으로만 부를 수 있게 한다
(`?force=metadata` 같은 형태). 실수로 갈 수 있는 길을 없앤다.

### E. 무엇이 달라졌는지 보이게

분석이 끝나면 로그에 한 줄:

```
analysis.replaced  mid=… segments=1027→1027 speakers=45→45 roles=0→2 verdict=WARN
```

**숫자가 나란히 있어야 나빠진 것을 안다.** 지금은 새 값만 찍는다.

## 3. 검증 계획 — 게이트를 시험할 수 있게 만드는 것이 핵심

게이트가 순수 함수여야 하는 이유가 이것이다. `tools/analysis-gate.test.mjs`:

| 심는 결함 | 기대 |
|---|---|
| 전사문이 빈 결과 | BLOCK |
| 세그먼트 1027 → 3 | BLOCK |
| `summary` 가 `⚠️ …` | BLOCK |
| 세그먼트 1027 → 1027, 화자 45 | OK 저장 + WARN 기록 |
| 역할 전부 미상 | WARN |
| 이름에 `]`·`` ` `` | WARN |
| 첫 분석(옛 결과 없음)에 전사문 있음 | OK — **처음이라고 막으면 안 된다** |
| 첫 분석에 전사문 없음 | BLOCK 아님 — 막을 옛것이 없다 |

**마지막 둘이 중요하다.** 게이트가 첫 분석을 막으면 제품이 안 돈다.
「막는 시험」 만 짜면 그걸 놓친다.

그리고 **게이트를 껐을 때 오늘의 사고 1이 재현되는지**를 시험으로 박는다 —
재현이 안 되면 그 시험은 무엇도 지키지 않는 것이다.

## 4. 순서와 크기

| | 무엇 | 왜 이 순서인가 |
|---|---|---|
| 1 | **B. 원자적 교체** | 사고가 아니라 **매번 일어나는 일**이다. 제일 먼저 |
| 2 | **A. 게이트 + 시험** | 사고 1을 막는다. B 위에 올라가야 롤백이 뜻이 있다 |
| 3 | **E. 나란히 로그** | 게이트가 무엇을 보고 판단했는지 되짚을 수 있어야 한다 |
| 4 | **C. 이전 판 보존** | 게이트가 놓친 것을 위한 그물. 마이그레이션이 필요하다 |
| 5 | **D. metadata 명시화** | 작다. 마지막에 |

**1~3 은 반나절, 4 는 반나절, 5 는 한 시간.** 마이그레이션 하나(`030`).
기존 표는 안 건드린다. **기존 데이터도 안 건드린다.**

---

## 5. 하지 않는 것

- **자동 재분석·자동 복구** — 되돌리는 것은 사람이 고른다
- **게이트를 넓게 잡는 것** — 「이상해 보이면 막는다」 로 가면 진짜 45명인 회의가 막힌다.
  BLOCK 은 「이건 결과가 아니다」 인 것만
- **기존 데이터 손보기** — 이미 저장된 것은 그대로 둔다

## 6. SEP v2 도 같은 모양이다

`SEP-V2.0` 의 `workflows/analysis.ts` 는 같은 구조다 — 같은 자리에서 같은 방식으로 덮는다.
LEP 에서 확인한 뒤 옮긴다. **먼저 한쪽에서 돌려 보고 옮긴다** — 두 곳을 동시에 고치면
어느 쪽에서 무엇이 깨졌는지 안 갈린다.
