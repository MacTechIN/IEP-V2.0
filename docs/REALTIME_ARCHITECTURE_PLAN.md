# 실시간 반응 + 백그라운드 심층분석 아키텍처 계획서
**작성일:** 2026-08-08 · **대상:** SEP v2.0 세일즈 미팅 분석
**목표:** Gemini Live처럼 **대화 중 실시간 반응**(감정 기복·이상/위험 감지·주의·기회)을 처리하면서, **백그라운드에서 청크를 심층 분석**해 세일즈 코칭 데이터(요약·코칭·스코어카드)를 생성하는 이중 구조.

---

## 0. 배경 — 현재 시스템과 한계
- **배치 분석**: 녹음 → `gpt-4o-transcribe-diarize`(화자분리 STT) → GPT로 리포트/코칭/5축 스코어카드/심리 생성. **품질 좋음.** 단, **STT가 2분에 ~100초로 매우 느림**(모델 특성).
- **근실시간 리스크 레이더**: 녹음 중 25초 webm 클립 → whisper 전사 → gpt-4o-mini 위험/기회 판정. **지연 ~25초**, 진짜 스트리밍 아님.
- **문제**: (1) diarize STT 100초 지연, (2) 실시간 반응이 25초 폴링이라 굼뜸, (3) 전사를 배치·레이더가 **따로 두 번** 함(중복 비용).

핵심 방향: **스트리밍 STT를 백본으로 삼아 "한 번 전사 → 두 루프가 공유"** 하면 세 문제를 동시에 해결한다.

## 1. 기술 조사 요약 (2026 중반 기준, 근사치)

### 1-1. 실시간 speech-to-speech API
| | Google Gemini Live | OpenAI Realtime |
|---|---|---|
| 전송 | WebSocket, PCM16 16kHz in / 24kHz out | WebSocket/WebRTC, PCM16 24kHz |
| 특징 | 네이티브오디오 **Affective Dialog**(톤 인지)·barge-in·함수호출·입출력 전사 | **server_vad / semantic_vad**·`input_audio_transcription`·함수호출 |
| 세션 한도 | **연결 ~10분**, 오디오 세션 15분(압축 시 무제한, 재개토큰 2h) | **~60분**(Azure 30분), 무음 지속 시 조기 끊김 |
| 지연 | 서브초 | 스피치-투-스피치 ~300~800ms |
| 가격 | 오디오 in $3 / out $12 (per 1M tok) ≈ **$3~6/hr** | 오디오 in $32 / out $64 ≈ **$3~6/hr**, mini ≈ $0.016/min |
| 용도 | "톤 이해 + 구조화 반응"을 한 소켓에서 | 반응 + 입력 전사를 한 곳에서 |

→ **주의:** 둘 다 **모델이 오디오를 생성**(TTS)하는 게 비용의 대부분. 우리는 **AI 음성 응답이 필요 없고**(코칭 카드만) → speech-to-speech는 과함. 세션 한도도 미팅 길이에 부담.

### 1-2. 스트리밍 STT + 실시간 화자분리 (권장 백본)
| | Deepgram Nova-3 | AssemblyAI Universal-Streaming |
|---|---|---|
| 지연 | **<300ms** | **~300ms**(불변 전사, 재작성 적음) |
| 실시간 화자분리 | 지원(자동 화자수) | 지원(`speaker_labels`, 최대 10, `max_speakers`) |
| 실시간 감정/토픽 | **❌ 배치 전용** | **❌ 배치 전용**(+LeMUR 배치 LLM) |
| 가격 | 스트리밍 **~$0.0077/min (~$0.46/hr)** | 스트리밍 **~$0.15/hr**, 배치+기능 ~$0.30~0.35/hr |

→ **결론:** 실시간 2인 화자분리는 둘 다 ~300ms로 충분. **감정/토픽/인텐트는 어느 벤더도 실시간 제공 안 함 → 우리 LLM을 전사문에 얹어야 함.** 지연·비용 우선이면 **Deepgram**, 불변전사+배치 인텔리전스 재활용이면 **AssemblyAI**.

### 1-3. 실시간 감정/이상/위험 감지
- **음향 감정(Hume AI)**: 목소리 톤에서 48차원 감정, 서브250ms, **~$3.8/hr**. 텍스트가 못 잡는 "말은 정상인데 격앙된 톤"을 잡음. 점수 노이즈 → 스무딩 필요.
- **텍스트 LLM 분류(현재 우리 방식)**: 전사문에 gpt-4o-mini → 감정/오브젝션/위험/기회. 싸고 유연, 단 STT+LLM 지연(~0.5~2s)·순수 음향 신호는 못 잡음.
- → **상보적.** 기본은 텍스트 LLM(싸다), **톤 기반 격앙/이탈 경보가 필요한 곳만 Hume** 추가.

### 1-4. VAD (비용 최대 절감 레버)
- **Silero VAD**(오픈소스, <1ms/30ms청크, 소음강함) — 클라이언트에서 **음성 구간만 업로드** → **~75% 비용 절감**(대화는 대부분 무음).
- WebRTC VAD(가볍지만 소음 약함). Realtime API의 server/semantic VAD는 스피치-투-스피치용.

### 1-5. 이중 루프 패턴 (문헌 근거)
- **Fast Brain / Slow Brain**, **VoiceAgentRAG**(Fast Talker + Slow Thinker), **dual-pipeline**(언어/음향 병렬), 프레임워크: **Pipecat / LiveKit Agents**.
- **Gong/Chorus 현실**: 사실상 **사후(post-call) 분석** 중심. **실시간 인콜 코칭은 아직 미개척 차별점**(Revenue.io 등 도전). → 베낄 표준 "라이브" 레퍼런스는 없음. 우리가 앞서갈 여지.

## 2. 권장 아키텍처 — 이중 루프 (이 앱 맞춤)

```
                         ┌──────────── 브라우저(미팅 중) ────────────┐
   [마이크] → Silero VAD(음성 구간만) ──WebSocket──▶ [백엔드 게이트웨이]
                         └───────────────────────────────────────────┘
                                            │ 오디오(음성 구간)
                                            ▼
                              [스트리밍 STT + 실시간 화자분리]   ← Deepgram/AssemblyAI (~300ms)
                                            │ 실시간 부분 전사(화자별)
                    ┌───────────────────────┼────────────────────────┐
             (Fast loop, <1~2s)                              (Slow loop, 수초~사후)
        rolling 전사창 → gpt-4o-mini                     누적 전사문 → 심층 LLM 분석
        위험/기회/감정 + 대응 스크립트                   리포트·코칭·5축 스코어카드·심리
        → 실시간 코칭 카드(🟢🟡🔴🔵)                     → 미팅 상세 저장(사후/주기)
        (옵션) Hume 음향 감정 병렬
```

**핵심 결정:** **스트리밍 STT를 단일 백본**으로 두고, 그 전사문을 **Fast loop(실시간 반응)와 Slow loop(심층분석)가 공유.** → (a) 100초 지연 제거, (b) 실시간 반응이 폴링이 아닌 스트림, (c) 전사 1회로 두 루프 공급(중복 비용 제거).

- **Fast loop**: rolling window(예: 최근 30~60초 전사)를 gpt-4o-mini로 판정 → 지금의 "리스크 레이더"를 **25초 폴링 → 스트리밍**으로 승격. 히스테리시스·동의·은근한 컬러 패널 UI는 그대로 재사용.
- **Slow loop**: 누적 전사문으로 리포트/코칭/스코어카드/심리(이미 구현됨) — 미팅 종료 시(또는 몇 분마다) 실행. **더 이상 별도 diarize 100초 불필요**(스트리밍 전사문 재사용).
- **공유/저장**: 실시간에서 뜬 위험/기회 지점을 **타임라인 마커**로 남겨 사후 복기(§Gong류 강점 + 라이브 차별점 결합).

## 3. 현재 → 목표 진화 경로 (무엇을 바꾸나)
| 구성 | 지금 | 목표 |
|---|---|---|
| STT | `gpt-4o-transcribe-diarize`(배치, ~100초) | **스트리밍 STT 벤더**(~300ms, 화자분리) |
| 실시간 반응 | 25초 webm 폴링 → whisper → mini | **스트리밍 전사 → mini**(지연 ↓, 폴링 제거) |
| 심층분석 | 별도 diarize 재전사 | **스트리밍 전사문 재사용** |
| 전사 횟수 | 배치+레이더 2회 | **1회(공유)** |
| 감정 | 텍스트 LLM만 | 텍스트 LLM + (옵션)Hume 음향 |

## 4. 단계별 도입안 (작업단위)

- **RT-0 (완료)** — 배치 파이프라인·근실시간 리스크 레이더(25초 폴링)·동의/히스테리시스.
- **RT-1 — 스트리밍 STT 백본 (핵심, 최우선)**
  - 백엔드 WebSocket 게이트웨이(Express `ws`) + nginx WS 프록시(`Upgrade`).
  - Deepgram/AssemblyAI 스트리밍 연동 → 실시간 화자분리 전사.
  - **효과:** 100초 지연 제거 + 실시간 전사 확보. *배치 STT도 이걸로 대체 가능(속도↑).*
- **RT-2 — Fast loop(실시간 코칭) 스트리밍화**
  - rolling 전사 → gpt-4o-mini 위험/기회/감정 → 실시간 카드. 기존 레이더 UI 재사용, 폴링 제거.
  - **VAD-gating(Silero)** 도입 → 비용 최대 절감.
- **RT-3 — Slow loop 통합**
  - 스트리밍 누적 전사문으로 리포트/코칭/스코어카드/심리(구현됨) 실행 → 종료 시 자동. 실시간 마커를 상세 타임라인에 저장.
- **RT-4 — 음향 감정(옵션)**
  - Hume 프로소디 병렬 → 톤 기반 격앙/이탈 경보 강화(비용 정당화되는 곳만).
- **RT-5 — 운영 완성도**
  - 세션 재개(연결 한도), 재연결/백프레셔, 비용 대시보드, 프라이버시(동의·구간 저장 정책).

## 5. 비용/지연 (시간당, 근사)
| 경로 | 지연 | 비용/hr |
|---|---|---|
| 스트리밍 STT (Deepgram/AssemblyAI) | ~300ms | **$0.15~0.46** |
| Fast 반응 LLM (mini, 트리거/주기) | <1~2s | 수십원~$1 |
| Slow 심층 LLM (배치) | 수초(사후) | 소액(호출당) |
| (옵션) Hume 음향 감정 | ~250ms | ~$3.8 |
| speech-to-speech(비권장) | ~300ms | $3~6 |

**절감 전략(핵심):** ① **VAD-gating**(음성 구간만 → ~75%↓) ② 무음 스킵/버퍼링 ③ **적응형 케이던스**(오브젝션·장문 발화 등 트리거 시에만 심층) ④ 티어 모델(실시간=mini, 사후=대형 배치) ⑤ **전사 재사용**(감정/토픽은 배치에서).

## 6. 확정 필요 결정
1. **스트리밍 STT 벤더**: **Deepgram**(지연·비용 최저, 단순 2화자) vs **AssemblyAI**(불변전사·배치 인텔리전스 재활용). → 권장: **Deepgram로 시작**, 배치 인텔리전스가 필요해지면 AssemblyAI 검토.
2. **speech-to-speech(Gemini/OpenAI Realtime) 사용?** → **비권장**(AI 음성 응답 불필요·세션한도·고비용). 전사+우리 LLM로 충분.
3. **Hume 음향 감정** 도입 시점(비용 vs 톤 신호 가치).
4. **실시간 계층 활성 조건**: 항상 vs 사용자 토글(비용 관리).

---

## 7. 리스크/주의
- **세션 한도**: Realtime speech-to-speech는 10~60분 한도 → 우리는 STT 스트리밍이라 상대적으로 자유롭지만 재연결 설계 필요.
- **프라이버시**: 실시간 감정 분석은 민감 → 동의 고지(구현됨) + 실시간 클립 즉시 삭제(구현됨) 정책 유지.
- **오탐**: 히스테리시스(구현됨) + VAD로 무음 오탐 감소.
- **벤더 종속**: STT 추상화 레이어를 두어 Deepgram↔AssemblyAI 교체 용이하게.

## 결론 (한 줄)
**"스트리밍 STT(화자분리)를 백본으로 두고, 하나의 전사 스트림을 Fast(실시간 코칭)·Slow(심층 분석) 두 루프가 공유"** — 이것이 100초 지연·폴링·중복비용을 한 번에 해결하며 Gemini Live식 실시간성과 Gong식 심층분석을 동시에 달성하는 길. **최우선 착수: RT-1(스트리밍 STT 백본).**
