# IEP 이미지 증적·참조 자료 기능 — 개발계획 (S7)

작성 2026-09-02 · 상태: 계획(미착수) · 관련 [2026-09-01-개발계획.md](2026-09-01-개발계획.md)

> 조사 중 수사관이 **관련 이미지를 촬영·업로드**하고, **왜 넣는지(입력 이유)**를 적고,
> 이미지를 **사실 위주로 분석**해, 분석 결과에 **증적 자료·참조 자료**로 엮는다.
> IEP 만의 신기능. LEP·SEP 에는 없다.

---

## 0. 대전제 — §0 을 이미지로 넓힌다

기존 §0(진술 분석)은 「판정하지 않고 근거를 짚는다」이다. 이미지도 똑같이 다룬다.

1. **이미지를 판정하지 않는다.** "이 사진은 범행 증거다", "조작됐다", 진위·유죄를 말하지 않는다.
   대신 **보이는 것을 사실로 적는다** — 문서면 텍스트(OCR), 사물, 장면, 수량.
2. **사람을 규정하지 않는다.** 얼굴로 신원을 추정하지 않는다("이 사람은 피의자다" 금지).
   보이는 사실만("사람 2명이 서 있다").
3. **입력 이유가 근거다.** 진술 분석에서 인용이 근거이듯, 이미지에서는 **수사관이 적은 「왜 넣는가」**가 근거다.
   이유 없는 이미지는 받지 않는다 — 목적 없는 사진은 증적이 아니라 잡음이다.
4. **증적은 손대지 않는다.** 원본을 변형하지 않고, 입력 시 해시(SHA-256)를 박아 **위변조를 검증**할 수 있게 한다.
   분석은 원본과 **별도**로 저장한다 — 분석이 원본을 덮지 않는다.
5. **전부 참고 자료다.** 이미지 설명은 판단이 아니라 **확인해 볼 자료**다. 판단은 수사관이 한다.

> 왜 이렇게 하나: 이미지 AI 가 「이 문서는 위조다」·「이 사람이 범인이다」를 말하면,
> 그 판정이 수사를 왜곡하고 법정에서 다툼거리가 된다. IEP 는 **보이는 것을 적고 근거를 남길 뿐**이다.

## 1. 세 가지 틀 (수평·수직·마이크로)

### 수평 (L1 저장 → L5 화면)

```
L1 저장    R2(이미지 원본·불변) · Neon(메타: 이유·해시·설명·연결)
L2 API     Worker(Hono) — 업로드 URL 발급 · 메타 저장 · 조회
L3 처리    Vision 분석(gpt-4o vision) — 사실 설명(OCR·사물·장면), 판정 아님
L4 실시간  (없음 — 이미지는 실시간 처리 대상이 아니다. 붙이고 나중에 분석)
L5 화면    녹음 화면: 촬영/업로드 + 이유 입력 · 조사 상세: 증적 자료 섹션 · 수사보고: 첨부
```

### 수직 (얹기)

```
V0 기반    R2 업로드 · 메타 테이블
V1 촬영·업로드   MediaDevices(카메라) · 파일 선택 · R2 저장 · SHA-256
V2 입력 이유     왜 넣는가(필수) · 어떤 진술/finding 과 관련되는가(선택)
V3 사실 분석     Vision → 설명·OCR·사물 (판정 아님, §0)
V4 연결·표시     조사 상세 증적 섹션 · 진술 finding 에 연결
V5 보고 통합     수사보고 「증적·참조 자료」로 엮기 (모델 없이 조립)
```

**Stackable:** V1~V2 만 배포해도 「이유를 적은 사진 증적」이 남는다(분석 없이도 값어치).
V3(분석)은 나중에 얹는다. V5(보고 통합)는 기존 조서 서식 재사용.

### 마이크로프로세스 유닛 (step/함수)

| 유닛 | 하는 일 | 시험 |
|---|---|---|
| `imageIngest` | 촬영/업로드 → R2 저장 + SHA-256 | 해시 일치·원본 불변 |
| `imageReason` | 입력 이유(필수)·연결 대상 받기 | 이유 없으면 거부 |
| ★ `imageDescribe` | Vision → 사실 설명(OCR·사물·장면), 판정 문구 차단 | 「위조·범죄·유죄」 어휘 거름 |
| `imageLink` | 특정 진술/finding 에 연결 | 링크 무결성 |
| ★ `imageDigest` | 수사보고에 증적으로 조립(이유+설명+해시) | 원본 값 그대로 |

★ = 새로 만드는 핵심 유닛.

## 2. 데이터 모델 (마이그레이션 035 예정)

```sql
create table v2.meeting_images (
  id            uuid primary key default gen_random_uuid(),
  meeting_id    uuid not null references v2.meetings(id) on delete cascade,
  r2_key        text not null,                 -- R2 원본 경로 (불변)
  sha256        text not null,                 -- 입력 시 해시 — 위변조 검증
  mime          text not null,
  bytes         integer not null,
  -- **입력 이유 — 필수.** 목적 없는 이미지는 증적이 아니다 (§0-3).
  reason        text not null,
  -- 특정 진술/확인점에 연결 (선택). 「피의자가 언급한 계약서」 ↔ 그 모순 finding.
  linked_finding_id uuid references v2.findings(id) on delete set null,
  -- Vision 사실 설명 (분석 후 채워짐). 원본과 별도 — 분석이 원본을 안 덮는다.
  description   jsonb,                          -- {summary, ocr_text, objects[], caution}
  analyzed_at   timestamptz,
  captured_by   uuid not null references v2.users(id),
  captured_at   timestamptz not null default now(),  -- 촬영/업로드 시각(증적 시간)
  created_at    timestamptz not null default now(),
  -- 이유는 반드시 채워져 있어야 한다(빈 문자열도 거부)
  constraint meeting_images_reason_required check (length(btrim(reason)) > 0)
);
```

증적 시간은 `captured_at`, 저장 시간은 `created_at` — 둘을 나눈다(촬영 시각과 업로드 시각이 다를 수 있다).

## 3. Vision 분석 — 무엇을 시키고 무엇을 막나 (imageDescribe)

**맡긴다:** 보이는 것의 사실 기술 —
- `summary` — 한두 문장 사실 요약("A4 계약서 1장. 상단에 '부동산 매매계약서' 제목.")
- `ocr_text` — 이미지 속 글자 그대로(문서·표지판·화면)
- `objects` — 보이는 사물/장면 목록

**막는다 (프롬프트 + 후처리로 이중 차단):**
- **판정 어휘 금지** — 「위조/조작/가짜/진짜/범죄/유죄/증거임/거짓」. 나오면 후처리에서 걸러 `caution` 으로 내린다.
- **신원 추정 금지** — 얼굴로 사람 지목("피의자다") 안 함. "사람 N명"까지만.
- **없는 것 지어내기 금지** — 흐릿해 안 보이면 "판독 불가"로 둔다.

출력에 항상 `caution: "이미지만으로 판단하지 않습니다. 원본·맥락을 사람이 확인하십시오."` 를 붙인다.

모델: `gpt-4o`(vision). `temperature: 0`. 같은 이미지에서 같은 설명이 나오게.

## 4. 화면 (L5)

### 녹음 화면 (UploadPage) — 붙이는 자리

```
[ 📷 사진 촬영 ]  [ 🖼 사진 업로드 ]      ← 녹음과 별개. 녹음 안 끊긴다.
그 자리에서:
  · 이미지 미리보기
  · 입력 이유 *  (필수, 예: "피의자가 언급한 계약서")
  · 연결(선택): 이 조사의 확인점 목록에서 고르기
  [ 붙이기 ]
```

카메라: `getUserMedia({video})` → 프레임 캡처 → JPEG. 업로드: 파일 선택(이미지 mime, ≤10MB).
**녹음 스트림과 별개**(자막·코칭과 같은 원칙) — 이미지 쪽이 실패해도 녹음은 계속.

### 조사 상세 — 「증적·참조 자료」 섹션 (진술 분석 탭 옆/아래)

각 이미지 카드: 썸네일 · **입력 이유**(수사관이 적은 것) · Vision 사실 설명 · 해시(앞 8자) · 연결된 확인점.
「이미지만으로 판단하지 않습니다」 문구 상시 표시.

### 수사보고 (imageDigest) — 조립형 서식에 한 절 추가

```
6. 증적·참조 자료
   1) [이유] 피의자가 언급한 계약서 사진
      · 설명: A4 계약서 1장. 상단 '부동산 매매계약서'. 하단 서명란 2곳.
      · 무결성: sha256 3f9a… (입력 2026-09-02 14:03, 홍길동 수사관)
      · 관련: [진술 간 모순] 계약서 서명 여부
   ※ 이미지는 참조 자료입니다. 판단은 수사관이 합니다.
```

기존 `documents/investigator.ts` 의 조립 방식 그대로(모델 없이). 원본 이미지는 링크/첨부.

## 5. 증적 무결성·프라이버시

- **해시로 위변조 검증** — 입력 시 SHA-256, 이후 재계산해 대조. 원본은 절대 변형·재인코딩 안 함.
- **출처(provenance)** — 누가(`captured_by`)·언제(`captured_at`)·왜(`reason`). 삭제는 사람이(감사 남김).
- **얼굴·PII** — Vision 이 신원을 지목하지 않는다. 원본 이미지 접근은 담당자로 제한(사건 소유자).
- **촬영 고지** — 대상·장소 촬영 시 고지·동의는 수사관 책임(기존 §6-C 와 같은 자리에 안내).
- **완전한 법적 chain-of-custody 는 아니다** — provenance + 해시까지. 이 한계를 화면에 적는다.

## 6. 단계 (S7)

| 단계 | 무엇 | 값어치 | 대략 |
|---|---|---|---|
| **S7-a** | 촬영/업로드 + 이유(필수) + R2 + 해시 (마이그레이션 035) | 이유 붙은 사진 증적이 남는다 | 하루 |
| **S7-b** | Vision 사실 분석(imageDescribe) — 판정 차단 | 사진 내용을 글로 검색·정리 | 하루 |
| **S7-c** | 조사 상세 증적 섹션 + 수사보고 통합(imageDigest) | 보고서에 증적으로 엮임 | 하루 |

**S7-a 만으로도 실사용 가능** — 분석 없이도 「이유 적힌 사진 증적」은 조사에 값어치가 있다.

## 7. 반드시 지킬 것 (요약)

- 이미지를 **판정하지 않는다**(위조·범죄·유죄·신원 금지). 보이는 사실만.
- **입력 이유 필수** — 이유가 이미지의 근거다.
- **원본 불변 + 해시** — 증적은 손대지 않는다.
- 전부 **참조 자료** — 판단은 수사관.
- 카메라/업로드는 **녹음과 별개** — 한쪽이 죽어도 녹음은 계속.

> 배포는 기존 절차 그대로(마이그레이션 035 → worker → web, 번들 확인·태그).
> 착수 전 이 계획을 코드로 재확인한다(계획서를 믿지 않는다 — CLAUDE.md).
