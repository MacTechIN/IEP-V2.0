# 화자별 대화 내려받기 — 계획

- 작성일: 2026-08-18
- 대상 버전: **v2.8.0** (기능 추가)
- 상태: **구현 완료 · 실제 미팅 확인과 배포 대기** (2026-08-18)
- 제약: **기존 기능은 한 줄도 바뀌지 않는다. 서버·DB 는 건드리지 않는다**

---

## 왜 필요한가

미팅 상세의 `💬 화자별 대화` 는 **화면 안에서만 산다.** 404개짜리 녹취를
동료에게 넘기거나 제안서에 붙이려면 지금은 마우스로 긁어 복사하는 수밖에 없는데,
스크롤 컨테이너 안이라 한 번에 다 잡히지도 않고 화자 이름이 본문과 뒤엉킨다.

첫 대상은 **"위바이K 해외구매대행플렛폼 개발 기획논의"** 미팅이다.
이 미팅의 화자별 대화 전문을 텍스트·워드·PDF 로 받을 수 있게 한다.

---

## 조사 결과

### 1. 내려받을 데이터는 이미 화면에 다 있다 ★

`MeetingDetailPage` 는 진입할 때 녹취 전체를 한 번에 받아 상태에 들고 있다.

```ts
// frontend/web/src/pages/MeetingDetailPage.tsx:110
apiClient.getTranscript(id)   →  setSegments(...)   // :121
```

서버 응답(`worker/src/services/meetings.ts:166 getSegments`)은 한 줄마다
`speakerLabel · content · startMs · sortOrder · editedAt · highlights · recordingId`
를 `sort_order` 순으로 준다. **필요한 것이 전부 들어 있고 이미 정렬돼 있다.**

→ **새 API 도, 새 컬럼도, 마이그레이션도 필요 없다.** 파일을 만드는 일은 전부 브라우저에서 끝난다.
   Worker 배포가 걸리지 않으므로 되돌리기도 웹 한 쪽만 되돌리면 된다.

### 2. 서버에서 만들면 오히려 손해다

내려받기 엔드포인트를 새로 파는 길도 봤으나 셋 다 손해다.

| | 문제 |
|---|---|
| 인증 | 토큰이 헤더에 실려 `<a href>` 로 바로 못 받는다. 결국 fetch → Blob → 저장이라 클라이언트 코드가 그대로 필요하다 |
| 중복 | 같은 녹취를 화면이 이미 받아 놓고 서버에서 또 읽는다 |
| 위험 | Worker 를 건드리면 배포가 API 까지 번진다. 화면만 바꾸는 일에 API 를 재배포할 이유가 없다 |

### 3. 버튼을 넣을 자리

```
frontend/web/src/pages/MeetingDetailPage.tsx:565   <Paper>            ← 화자별 대화 패널
                                            :570   <Box onClick=접기/펼치기>   ← ★ 함정
                                            :574     💬 화자별 대화
                                            :575     <Box 가로줄>
                                            :578       발화 404개 · 화자 3명
                                            :582       [펼치기]
                                            :588   <Collapse>
```

**`:570` 의 Box 전체가 접기/펼치기 클릭 영역이다.** 그 안에 버튼을 넣으면
누를 때마다 패널이 같이 접힌다 — `e.stopPropagation()` 이 반드시 있어야 한다.

넣는 자리는 **`:582` 펼치기 버튼 왼쪽**이다. 접힌 상태에서도 눌러야 하므로
`Collapse` 안(검색·필터 줄)에 두면 안 된다 — 내려받으려고 먼저 펼치게 만드는 꼴이다.

`:566` 주석이 이미 경고하고 있다 — 한 줄에 제목·요약·버튼을 몰아넣었더니
좌우 분할에서 제목이 "화자별 / 대화" 로 접혔다. 그래서 **글자 버튼이 아니라
아이콘 버튼 하나(⤓)**로 넣고, 형식 선택은 메뉴로 편다. 폭을 40px 만 먹는다.

### 4. 한글 PDF 가 이 일의 유일한 난관

jsPDF·pdf-lib 같은 클라이언트 PDF 라이브러리는 **내장 폰트에 한글이 없다.**
넣으려면 Noto Sans KR 을 서브셋해 바이너리로 싣는 수밖에 없고, 상용 2,780자만
잡아도 1MB 안팎이 붙는다. 지금 번들이 **726,634 바이트**(2026-08-14 빌드)인데
PDF 하나 때문에 두 배가 된다.

**→ 인쇄 대화상자로 간다.** 브라우저의 "PDF로 저장"은 시스템 한글 폰트를 그대로 쓰고,
줄바꿈·페이지 나눔·목차를 브라우저가 처리하며, **번들이 0바이트 늘어난다.**

## 만들 것

### 새 파일 둘 + 테스트 하나

```
frontend/web/src/lib/transcriptExport.ts        문서 모델과 세 형식 생성기
frontend/web/src/components/TranscriptDownload.tsx   버튼 + 형식 메뉴
frontend/web/tests/transcript-export.test.ts    형식·파일명 회귀 테스트
```

**형식마다 따로 짜지 않는다.** 가운데에 문서 모델 하나를 두고 셋이 그것을 읽는다 —
안 그러면 머리말을 고칠 때 세 군데를 고쳐야 하고, 반드시 한 군데를 빠뜨린다.

```
segments ──▶ buildDoc() ──▶ TranscriptDoc ──┬─▶ toPlainText()  ──▶ .txt
                                            ├─▶ buildDocx()    ──▶ .docx
                                            └─▶ toPrintHtml()  ──▶ 인쇄창
```

```ts
interface TranscriptDoc {
  title: string
  meta: { label: string; value: string }[]   // 일시 · 고객사 · 발화 수 · 화자 수 · 내려받은 시각
  blocks: { speaker: string; lines: string[] }[]
}
```

**`blocks` 가 줄이 아니라 덩어리인 이유**: 같은 화자가 연달아 말한 것을 한 덩어리로 묶는다.
404줄에 `[영업대표]` 가 404번 반복되면 사람이 읽을 수 있는 문서가 아니다.
실측 기준 404개 발화가 화자 덩어리로는 100~150개로 줄어든다.

### 고칠 파일

```
frontend/web/src/pages/MeetingDetailPage.tsx    :582 위에 버튼 한 줄
frontend/web/package.json                        docx 의존성 + 버전
worker/package.json · stream-service/package.json  버전만 (셋은 같이 움직인다)

```

## 출력 형식

### 텍스트 (.txt)

```
위바이K 해외구매대행플렛폼 개발 기획논의
────────────────────────────────────────
일시        2026-08-14 14:00
고객사      (주)위바이케이
발화        404개 · 화자 3명
내려받은 때  2026-08-18 21:03
────────────────────────────────────────

[영업대표]
안녕하세요, 오늘 시간 내주셔서 감사합니다.
지난번에 말씀하신 해외 구매대행 쪽부터 보겠습니다.

[고객]
네, 반갑습니다.
```

- 줄바꿈은 **CRLF** 다. Windows 메모장이 LF 만 있는 파일을 한 줄로 뭉갠다
- BOM(`﻿`) 을 붙인다. 없으면 엑셀·구형 메모장이 한글을 깨뜨린다
- MIME `text/plain;charset=utf-8`

### 워드 (.docx)

`docx` 라이브러리로 **진짜 OOXML** 을 만든다.

HTML 에 `.doc` 확장자를 붙이는 흔한 편법은 쓰지 않는다 — Word 가
"파일 형식과 확장명이 일치하지 않습니다" 경고를 띄우고, 구글 문서에서는 깨진다.
받은 사람이 경고창부터 보는 파일은 내보내기가 아니다.

| 부분 | 스타일 |
|---|---|
| 제목 | Heading 1 |
| 머리말 | 테두리 없는 2열 표 (라벨·값) |
| 화자 이름 | 굵게, 위 간격 8pt, **다음 문단과 붙임**(`keepNext`) |
| 발화 | 본문 문단, 줄 간격 1.15 |

문서 속성(제목·작성자 `SEP`)도 채운다 — 파일 목록에서 제목이 보인다.

**초기 번들에 넣지 않는다.** 메뉴에서 워드를 고른 순간 `await import('docx')` 로
받는다. Vite 가 알아서 별도 chunk 로 떼어내므로 `index-*.js` 는 그대로다.

### PDF (인쇄)

숨은 `<iframe>` 을 만들고 `srcdoc` 에 인쇄용 HTML 을 넣은 뒤 `contentWindow.print()`.

**`window.open` 을 쓰지 않는다** — 팝업 차단기에 막히면 아무 일도 안 일어나고
사용자는 왜 안 되는지 알 수 없다. iframe 은 차단 대상이 아니다.

```css
@page { size: A4; margin: 18mm 16mm; }
body  { font-family: -apple-system, "Malgun Gothic", "Noto Sans KR", sans-serif;
        font-size: 10.5pt; line-height: 1.6; }
.speaker { font-weight: 700; margin-top: 12px; break-after: avoid; }
.block   { break-inside: avoid; }
```

`break-after: avoid` 가 없으면 화자 이름만 페이지 맨 아래 남고 말은 다음 장으로 넘어간다.

인쇄가 끝나면 iframe 을 지운다. `onafterprint` 를 걸되 **10초 타이머도 같이 건다** —
Safari 는 `onafterprint` 를 부르지 않을 때가 있고, 그러면 iframe 이 계속 쌓인다.

## 파일 이름

```
위바이K 해외구매대행플렛폼 개발 기획논의_화자별대화_2026-08-18.txt
```

- 금칙 문자 `\ / : * ? " < > |` 와 제어문자를 `_` 로 바꾼다 (Windows 가 거부한다)
- 앞뒤 공백·마침표를 떼고 120자에서 자른다
- 제목이 비었으면 `미팅` 을 쓴다
- 날짜는 **미팅 날짜**다. 내려받은 날이 아니다 — 같은 미팅을 두 번 받아도 같은 이름이어야 한다

## 걸릴 곳 (미리 적어 둔다)

| 함정 | 대응 |
|---|---|
| 버튼을 누르면 패널이 접힌다 | `onClick={(e) => e.stopPropagation()}` (`:570` 의 Box 가 클릭 영역이다) |
| 팝업 차단으로 인쇄창이 안 뜬다 | `window.open` 대신 숨은 iframe |
| Safari 가 iframe 을 안 치운다 | `onafterprint` + 10초 타이머 |
| 메모장에서 한 줄로 붙는다 | CRLF + BOM |
| Word 경고창 | 진짜 .docx (HTML+`.doc` 편법 금지) |
| 번들이 커진다 | `docx` 는 동적 import. 빌드 후 `index-*.js` 크기 대조 |
| 녹취가 없다 | 패널 자체가 `segments.length > 0` 일 때만 그려진다(`:564`) — 버튼도 자동으로 사라진다 |
| 화자 이름이 없는 줄 | `speakerLabel` 이 비면 `알 수 없음`. 화면 집계(`:169`)와 같은 규칙을 쓴다 |
| 만드는 동안 두 번 누른다 | 만드는 중에는 메뉴 항목을 비활성화하고 `⏳` 를 보인다 |
| 모바일 인쇄 | iOS·안드로이드도 인쇄를 지원한다. 다만 메뉴 항목에 `PDF (인쇄)` 라고 적어 인쇄창이 뜰 것을 미리 알린다 |

## 단계

**0. 대상 확인** — "위바이K 해외구매대행플렛폼 개발 기획논의" 를 화면에서 열고
미팅 id 와 발화 수를 적어 둔다. (접속 문자열이 로컬에 없어 DB 로는 못 찾는다)
→ **아직 안 했다.** 배포 뒤 이 미팅으로 세 형식을 받아 확인한다.

**1. 문서 모델 + 텍스트** — `transcriptExport.ts` 와 `.txt` 저장까지.
   여기서 형식이 확정되므로 실제 미팅 데이터로 눈으로 본다.
   *끝난 증거*: 받은 `.txt` 를 메모장에서 열어 줄바꿈·한글이 멀쩡하다.

**2. UI 결선** — 버튼과 메뉴를 붙인다. 이 단계에서는 텍스트만 동작한다.
   *끝난 증거*: 접힌 상태에서 버튼을 눌러도 패널이 접히거나 펼쳐지지 않는다.

**3. 인쇄 PDF** — 인쇄용 HTML + iframe.
   *끝난 증거*: 인쇄 미리보기에서 화자 이름이 페이지 끝에 홀로 남지 않는다. 저장한 PDF 의 한글이 깨지지 않는다.

**4. 워드** — `docx` 동적 import.
   *끝난 증거*: Word 와 구글 문서 양쪽에서 경고 없이 열린다. 빌드 후 `index-*.js` 크기가 726,634 에서 거의 그대로다.

**5. 테스트·배포** — 아래 두 절.

각 단계는 그 자체로 배포 가능하다. 2번까지만 올려도 텍스트 내려받기는 동작한다.

2. `CHANGELOG.md` 맨 위에 항목 — 위 숫자와 커밋 해시를 넣는다
3. `cd frontend/web && npx tsc --noEmit && npm run build:prod`
4. `gh workflow run "Deploy" --repo MacTechIN/SEP-V2.0`
5. 번들 대조: `curl -s https://sep-v2-web.pages.dev/ | grep -o 'index-[A-Za-z0-9_-]*\.js'`
6. `git tag -a v2.8.0 -m "…"` · `git push origin main --follow-tags`

마이그레이션 없음. `docs/ARCHITECTURE.md` 수정 없음 — 계층도, 배포 대상도, 표도 바뀌지 않는다.

---

## 되돌리는 법

웹 한 쪽만 되돌리면 된다. Worker·DB 는 손대지 않았으므로 **되돌릴 것이 없다.**
`git revert` 후 `Deploy` 를 다시 돌리면 버튼이 사라지고 나머지는 그대로다.

## 하지 않는 것 (범위를 여기서 닫는다)

- **서버 내보내기 엔드포인트** — 데이터가 이미 화면에 있다 (조사 2)
- **미팅노트·리포트 내보내기** — 이번 요청은 화자별 대화다. 문서 모델이 남으니 나중에 붙이기 쉽다
- **필터를 반영한 내보내기** — "항상 전체" 로 확정
- **발화 시각·수정 표시·형광펜** — 확정된 내용에서 뺐다
- **여러 미팅 일괄 내려받기** — 목록 화면 일이다
- **폰트 내장 PDF** — 인쇄로 간다. 한 번 클릭이 꼭 필요해지면 그때 다시 본다
