없는 것은 기능이 아니라 운영입니다 — 요금제, 사용량 제한, 온보딩, 장애 대응. 검증용이라 필요 없었던 것들입니다.

2 · 검증 결과 — 자막 엔진을 바꿀 것인가

"OpenAI 하나로 통합하면 벤더가 줄지 않나" 를 실제 오디오로 측정했습니다. 회수한 실제 미팅 녹음 60초 × 2구간, 같은 조건.

엔진방식일치도뽑아낸 글자첫 결과
gpt-transcribe파일70.1%198자3,190ms
gpt-4o-transcribe파일69.1%200자2,808ms
whisper-1파일69.0%188자3,298ms
Deepgram nova-2스트리밍64.4%190자5,673ms
gpt-4o-mini-transcribe파일63.7%103자2,406ms
OpenAI 실시간스트리밍46.6%95자8,870ms

일치도는 나머지 엔진들과 문자 단위로 얼마나 겹치는가입니다(정규화 후). 사람이 검수한 정답이 없으므로 절대 정확도가 아니라 다수결 대비 일치입니다.

결론: 옮기지 않는다

정확도 차이보다 누락이 결정적입니다. 스트리밍끼리 비교하면 Deepgram 190자, OpenAI 실시간 95자 — 절반을 놓칩니다. 두 샘플 모두에서 그랬고, 두 번째 샘플에서는 일치도가 39.4%까지 떨어졌습니다.

원인은 제가 쓴 설정의 서버 VAD 로 보입니다. 발화가 겹치고 배경음이 있는 미팅에서 많이 버립니다. 다른 설정이면 나아질 수 있으니 "OpenAI 실시간이 나쁘다" 로 단정하지는 않습니다 — 다만 기본 설정으로 바로 갈아탈 수 있는 상태가 아닙니다.

요금도 이유가 되지 못합니다. 둘 다 분당 약 $0.006 로 거의 같습니다. 게다가 Deepgram 은 화자 구분을 주는데 OpenAI 실시간은 주지 않습니다.

재검토 시점: OpenAI 가 실시간 전사에 화자 구분을 추가하거나, VAD 를 끄고 연속 전사하는 옵션이 생기면 다시 잽니다.

3 · 상용 전 남은 것

순서는 막고 있는 정도로 정했습니다. 앞의 것이 끝나야 뒤가 의미 있는 경우가 많습니다.

1단계 지금 열려 있는 것 닫기 1주

기능이 아니라 지금 상태로 남에게 보여줄 수 없는 것들입니다.

  • 회귀 검증 실행 — 계획서(docs/2026-08-11-regression-test-plan.md)가 승인 대기 중. 스무 개 넘게 고쳤는데 그중 둘은 이미 한 번 되깨진 적이 있습니다
  • 실시간 자막 브라우저 확인 — 게이트웨이 쪽은 실측했으나 브라우저의 오디오 변환은 미검증
  • 사내 서버 종료 — 데이터·통로 모두 옮겼고 24시간 트래픽 0. 멈추기만 하면 됩니다
  • 검증용 계정 정리 — zz-검증@, scope-check@, pilot-…@
2단계 여러 사람이 써도 버티게 2~3주

지금은 쓰는 사람이 적어서 문제가 안 되는 것들입니다.

  • 사용량 상한 — v1 에는 있고(일 20회/사용자, 50회/조직) v2 에는 없습니다. STT 는 20분 오디오당 약 $1.27 이라, 버튼을 반복해 누르는 것만으로 비용이 쌓입니다
  • 비용 가시화 — 조직별·사용자별 사용량을 볼 수 있어야 요금제를 정할 수 있습니다
  • 업로드 크기·길이 제한 — 지금은 사실상 무제한
  • 동시 분석 제한 — 한 조직이 열 건을 한꺼번에 걸면 다른 조직이 밀립니다
  • 실패 알림 — 분석이 실패해도 사용자가 화면을 열어야만 압니다
3단계 팔 수 있는 제품으로 3~4주
  • 조직 가입 흐름 — 지금은 관리자가 직접 넣습니다. 초대 · 가입 · 첫 설정이 필요합니다
  • 요금제와 결제 — 상한을 요금제에 묶고 초과 시 처리를 정해야 합니다
  • 온보딩 — 목소리 등록, 첫 녹음, 리포트 읽는 법을 안내하는 흐름
  • 데이터 내보내기 — 미팅 노트·리포트를 PDF/문서로. 고객이 가장 먼저 요구하는 것입니다
  • 보관 정책을 조직이 정하게 — 지금은 90일 고정입니다
4단계 운영할 수 있게 2주
  • 장애 감지 — 지금은 로그를 사람이 봐야 압니다. 분석 실패율·응답 시간에 알림이 필요합니다
  • 정기 감사 자동화 — R2 감사와 DB 상태 점검을 주기 실행하고 결과만 통지
  • 백업과 복구 절차 — Neon 백업은 있으나 복구를 해 본 적이 없습니다
  • 개인정보 처리 문서 — 어떤 데이터가 어디로 가는지(OpenAI·Deepgram·Google) 정리. 기업 고객이 반드시 묻습니다
이후 있으면 좋은 것 —
  • 미팅 검색 (지금은 목록만)
  • 고객사별 히스토리 · 추세
  • 팀 단위 비교 · 벤치마크
  • 모바일 대응 (지금은 데스크톱 기준)
  • MeetingDetailPage 분해 (2,300줄 넘음)
  • 번들 코드 분할 (700KB)

기술이 아니라 결정이 필요한 항목입니다. 이것들이 정해지지 않으면 3단계를 시작할 수 없습니다.

결정 사항왜 지금
가격 구조 미팅당 원가가 분석 $2~4 + 실시간 $0.7 수준입니다. 정액인지 종량인지에 따라 상한 설계가 달라집니다
데이터 보관 기간 지금 90일 고정. 고객이 정하게 할지, 요금제로 나눌지
녹음 원본 보관 여부 전사가 끝나면 오디오를 지울 수도 있습니다. 저장 비용과 재분석 가능성의 맞교환입니다
외부 서비스 고지 범위 음성이 OpenAI·Deepgram·Google 로 갑니다. 어디까지 계약서에 명시할지
실시간 기능 기본값 현재 꺼짐. 요금제에 포함할지 별도 옵션으로 할지

제한된 고객 몇 곳으로 파일럿을 먼저 여는 것입니다. 그러면 3단계(가입·결제)를 미루고 1·2단계만으로 시작할 수 있습니다 — 3~4주. 계정은 수동으로 만들고, 요금은 청구서로 받으면 됩니다.
