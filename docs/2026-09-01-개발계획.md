# IEP v2.0 — 개발 계획

**Investigate Enablement Platform · 대한민국 경찰 수사업무 지원 음성분석 시스템**

2026-09-01 착수 · 모체 LEP v2.1(← SEP v2) · **기존 SEP·LEP 와 완전 독립**

---

## 0. 설계 대전제 — 「판정」이 아니라 「근거를 짚는다」

경찰 수사에서 **거짓말 탐지·심리 판정은 만들지 않는다.** SEP 에서 함께 내린 결론과
같다(`SEP-V2.0/docs/2026-08-27-거짓말-탐지-하지-않음.md`). 이유가 수사에서 더 무겁다:

- **작동하지 않는다** — 음성 스트레스 분석 우연 수준, NRC 2003 폴리그래프도 개인 판정 근거 불충분
- **되돌릴 수 없다** — 오판·강압 자백. 「거짓 87%」 를 수사관이 믿고 신문하면 무고를 만든다
- **법정에서 깨진다** — 그런 판정에 기반한 조사는 증거능력·적법절차에서 무너진다

**요청하신 「거짓말·컨텍스트 불일치·이상한 부분」은 판정이 아니라 근거로 구현한다:**

| 요청 | IEP 의 구현 (판정 안 함) |
|---|---|
| 거짓말 탐지 | **진술 간 모순** — 같은 조사 안에서 어긋나는 두 발언을 **원문 인용 2개**로 |
| 컨텍스트 불일치 | **말이 바뀜** — 이전 조사·진술과 달라진 지점을 인용으로 |
| 이상한 부분 | **미확인 주장** — 확인 가능한데 근거가 안 나온 것(시간·장소·인물·금액) + 「무엇을 물어 확인하나」 |
| 심리분석 후 행동대처 | **진술 태도 변화** — 특정 주제에서 회피·화제 전환이 반복되는 지점을 **가리키기만** |
| 신문이 올바르게 가는지 | **절차 가이드** — 유도신문·권리고지 누락·진술거부권 관련을 짚는다 (수사관을 돕고, 대상자 권리도 지킨다) |

**원칙 다섯 (LEP 서면 생성에서 검증된 것 그대로):**
1. **인용 없으면 담지 않는다** — 모델이 지목한 문장이 실제 전사에 있는지 코드가 대조, 없으면 버림
2. **점수를 매기지 않는다** — 「신뢰도 72점」 같은 숫자는 근거 없이 그럴듯해 보여 가장 위험
3. **사람이 아니라 문장을 가리킨다** — 「대상자가 거짓」 이 아니라 「이 두 발언이 어긋남」
4. **무엇을 하면 되는지 함께 준다** — 다음에 확인할 질문. 짚기만 하면 의심만 남는다
5. **코칭도 보고서에 남는다** — 실시간으로 짚은 것이 조사 후 요약에 한 절로 정리된다 ← 요청사항

> 이 전제가 「최고의 수사 지원」과 충돌하지 않는다. **오히려 이것이 법정에서 살아남는 유일한 설계다.**

## 1. 세 축으로 본 구조

### 1-A. Horizontal — 모든 기능이 지나는 계층 (가로)

```
┌─────────────────────────────────────────────────────────────┐
│ L5  화면      React + MUI (조사 녹음·실시간 코칭·조서/보고서)      │
├─────────────────────────────────────────────────────────────┤
│ L4  엣지 API  Cloudflare Worker (Hono) — 인증·라우트·권한       │
├─────────────────────────────────────────────────────────────┤
│ L3  파이프라인 Cloudflare Workflow — step.do() 단위 분석         │
├─────────────────────────────────────────────────────────────┤
│ L2  실시간    Cloud Run (ws) — 20~30초 클립 코칭·실시간 자막      │
├─────────────────────────────────────────────────────────────┤
│ L1  저장      R2(오디오) · Neon Postgres(구조화 데이터)          │
└─────────────────────────────────────────────────────────────┘
```

L1~L5 는 **LEP 에서 이미 검증됐다.** IEP 는 이 가로 계층을 **그대로** 쓰고,
바뀌는 것은 L3 의 「분해」 단계와 L5 의 도메인 언어뿐이다(§2).

### 1-B. Vertical Stackable — 기능을 독립 슬라이스로 쌓는다 (세로)

각 슬라이스는 L1~L5 를 관통하는 **완결된 세로 조각**이고, **하나씩 켜고 끌 수 있다.**
아래에서 위로 쌓되, **아래가 없으면 위가 못 선다**(의존 방향).

```
  V7  코칭→보고서 통합    실시간으로 짚은 것을 조사보고서 한 절로 요약   ← 요청 핵심
  V6  조서·보고서 생성    조사 자료로 초안 (LEP 서면 생성 틀 재사용)
  V5  진술 분석          모순·미확인·태도변화·절차점검 (판정 아님)     ← §0
  V4  실시간 코칭         20~30초 클립 → 진행 가이드 (세일즈 코칭 대체)
  V3  화자·역할          병합·역할판정 (수사관/대상자/참여자)
  V2  전사              조각 분할·선처리·재사용 (docs/chunked-preprocess-pattern)
  V1  녹음·업로드        MediaRecorder 10분+15초 겹침 · R2 저장
  ──────────────────────────────────────────────
  V0  기반              인증·조사(case)·대상자·세션·배포·백업        ← 먼저 선다
```

**Stackable 의 값:** V5 까지만 배포해도 제품이 돈다(녹취+분석). V6·V7 은 나중에 얹는다.
반대로 V4(실시간)는 독립이라 빼도 V1~V3·V5 가 동작한다.

### 1-C. Microprocess Unit — 가장 작은 독립 처리 단위

L3 파이프라인은 **`step.do()` 단위**로 쪼개져 있고, 각 단위는 **독립 재시도·독립 시험**된다.
LEP 에서 이미 이렇게 검증했다. IEP 의 마이크로유닛(★ = 새로 만들 것, 나머지는 LEP 이관):

| 단위 | 하는 일 | 시험 |
|---|---|---|
| `transcribeChunk` | 조각 하나 STT | 선처리 재사용 대조(`storage_path`) |
| `mergeSpeakers` | 구간 넘어 화자 잇기 | 겹침 정렬·겹침없음 표시 |
| `mapRoles` | 역할 판정(숫자로 물음) | 상위 N명·미판정 미상 |
| `analysisGate` | 덮기 전 검증 BLOCK/WARN/OK | 첫 분석 안 막음·결함 심기 |
| `insertBatch` | 전사 묶음 삽입(원자적) | 자리표 대조 |
| ★ `statementCheck` | 모순·미확인·태도변화 (인용 대조) | 지어낸 인용 걸러냄 |
| ★ `procedureGuard` | 절차 점검(유도신문·권리고지) | 규칙별 탐지 |
| ★ `coachingDigest` | 실시간 코칭을 보고서 절로 요약 | 코칭 이벤트→요약 매핑 |

**마이크로유닛 규칙:** 한 단위는 (1) 순수 함수로 시험 가능하거나(게이트·인용대조),
(2) 실패해도 파이프라인 전체를 안 죽인다. **결함을 심어 시험이 잡는지 확인**한다(LEP 규율).

## 2. LEP → IEP 도메인 치환 (무엇을 갈아끼우나)

**뼈대(V0~V4)는 거의 그대로. 바뀌는 것은 L3 「분해」와 L5 언어.**

| LEP (영업/법률) | IEP (수사) | 작업량 |
|---|---|---|
| 영업대표 / 고객 / 변호사 / 의뢰인 | **수사관 / 대상자(피의자·참고인·피해자) / 참여자** | 라벨·역할판정 프롬프트 |
| `legalAnalysis` (요건사실·청구원인) | ★ `investigationAnalysis` (진술요지·쟁점·확인필요) | 새 서비스 1개 |
| `documents/complaint` (소장) | ★ `documents/statement` (진술조서·수사보고 초안) | 서식 1개(틀 재사용) |
| `matters` (사건=민사) | `cases` (사건=수사) | 표 이름·필드 조정 |
| 딜 신호·미팅 점수 (영업 척도) | **제거** (SEP·LEP 에서 이미 걷어낸 것과 같다) | 삭제 |
| 실시간 코칭(영업 리스크) | ★ 실시간 코칭(진행 가이드·놓친 질문·모순 알림) | 프롬프트 교체 |

**새로 만드는 코드는 서비스 3~4개 + 서식 1개.** 나머지는 이관·개명이다.

## 6. 확정 사항 (2026-09-01)

1. **git 저장소** — `MacTechIN/IEP-V2.0` **신규 생성**
2. **대상자 역할** — **피의자 · 참고인 · 피해자 · 목격자 · 수사관**으로 나눈다.
   **조사 목적(kind)도 나눈다** — §6-A
3. **적법절차 = 참고 자료다. 조사에 영향을 주지 않는다** — §6-B ★ 핵심 방향
4. **녹화 고지·동의 필요** — §6-C
5. **데이터 격리** — 수사자료는 민감도 최고. R2·Neon 접근기록·암호화 강도 최상(S1 에서 확정)

### 6-A. 대상자 역할 · 조사 목적 분류

**대상자 역할** (녹화 의무·권리 고지가 역할마다 다르다):

| 역할 | 설명 | 유의 |
|---|---|---|
| **수사관** | 조사를 진행하는 쪽 | 발화 주체, 코칭 대상 |
| **피의자** | 범죄 혐의를 받는 사람 | 진술거부권·변호인 조력권 고지 대상. 영상녹화 규정 |
| **참고인** | 사건 관련 정보를 가진 제3자 | 임의성 원칙 |
| **피해자** | 피해를 입은 사람 | 2차 피해 방지, 신뢰관계인 동석 |
| **목격자** | 사건을 본 사람 | 기억 오염 주의 |

**조사 목적(kind)** — 분석·코칭·보고서가 이 값으로 갈린다:

| 목적 | 설명 | 분석 초점 |
|---|---|---|
| `interrogation` **피의자 신문** | 혐의 사실 확인 | 진술 모순·미확인 주장·절차 점검 |
| `witness` **참고인 조사** | 정보 수집 | 진술 요지·확인 필요 사항 |
| `victim` **피해자 조사** | 피해 사실 청취 | 요지 정리, **판정·압박 코칭 없음** |
| `interview` **일반 면담/대화** | 예비·임의 대화 | 요지·다음 확인 사항 |
| `meeting` **수사 회의** | 수사관 간 회의 | 결정·다음 할 일 (대상자 분석 없음) |

**피해자 조사(`victim`)에는 「모순 짚기」·압박성 코칭을 걸지 않는다.** 2차 피해 방지.

### 6-B. ★ 적법절차·분석은 「참고 자료」다 — 조사에 영향을 주지 않는다

**이것이 IEP 전체의 방향을 정한다.**

> 모든 분석·코칭·절차 점검은 **조사관 개인의 참고 자료**일 뿐이다.
> **조사 진행이나 판단을 대신하거나 강제하지 않는다.**

- 화면·보고서에 나오는 모든 짚음은 **「참고」** 로 명시한다. 「이렇게 하라」 가 아니라 「확인해 보라」
- 절차 가이드(유도신문·권리고지)는 **경고가 아니라 알림**이다 — 조사관이 보고 판단한다
- **자동 결정·자동 개입 없음.** 시스템은 짚고, 사람이 정한다 (SEP `storage_orphans` 규율과 같다)
- 법률·내부규정 검토가 **실제 절차 규칙을 넣기 전에 먼저**다. 그전까지 절차 가이드는
  일반 원칙(유도신문 형태·권리고지 문구 유무) 수준으로만 두고, 기관 규정은 검토 후 얹는다
- 보고서 어디에도 **「AI 판정」·「거짓」·점수**가 안 나온다. 인용과 「확인할 것」만 나온다

### 6-D. ★ 호칭 — 수사관·대상자를 정확히 구분한다

**요청 확정 (2026-09-01): 화자 호칭을 잘못 붙이면 조사 전체가 틀린다.**
피의자의 진술이 수사관 것으로, 또는 그 반대로 라벨되면 — 모순 짚기·보고서·인용이
**전부 거짓이 된다.** LEP 의 화자 45명 사고보다 이 오류가 더 치명적이다.

원칙:
- **역할은 「추정」이므로 화면에 「추정」으로 표시하고, 사람이 고칠 수 있게 한다.**
  LEP 요건사실처럼 **사람이 고친 것은 AI 가 덮지 않는다**(`set_by='human'`)
- 역할 판정은 **말수만으로 정하지 않는다.** 수사관이 말수가 적을 수도(대상자가 길게 진술),
  많을 수도(추궁) 있다. **발화 내용**으로 판정하되, 확신 없으면 **「미상」**으로 두고
  사람이 지정하게 한다 — 틀린 호칭보다 빈 호칭이 낫다
- **조사 시작 시 수사관이 자기 화자를 먼저 지정**하는 길을 둔다(등록 목소리 or 첫 발화 지정).
  그러면 나머지가 대상자로 좁혀진다
- **한 조사에 대상자가 여럿**(피의자+참고인)이면 각자 다른 역할로 나눈다. 뭉치지 않는다
- 인용·보고서에 나오는 호칭은 **역할 그대로**(「수사관」/「피의자」/「참고인」/「피해자」/「목격자」),
  기호(`화자 A`)나 실명 추정 없이. 실명은 대상자 정보에서 사람이 넣은 것만 쓴다
- **미확정 호칭으로는 분석을 강행하지 않는다** — 역할이 「미상」인 발화가 많으면
  분석 게이트가 WARN 을 달아 「호칭을 먼저 확인하라」고 알린다

즉 **호칭은 시스템이 짚고 사람이 확정한다**(§6-B 참고 자료 원칙과 같다).

### 6-C. 녹화 고지·동의

- 녹음/녹화 **시작 전에 고지·동의 화면**을 둔다. 동의 없이 녹음 버튼이 안 눌린다
- 조사 목적·대상자 역할에 따라 **고지 문구가 달라진다**(피의자=진술거부권 포함)
- **누가·언제 고지·동의했는지 접근기록에 남긴다** (LEP `access_log` 재사용)
- 형사소송법 영상녹화 규정과 맞물리므로 **문구 자체는 법률 검토 대상** — S1 에 자리, 검토 후 확정
