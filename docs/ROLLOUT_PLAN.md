## 🚀 롤아웃 전략

### **3단계 점진적 롤아웃**

#### **1️⃣ Canary 배포 (1일)**
**기간:** 2026-10-01

**대상 사용자:** 5명 (매니저 + 초기 채택자)

**목표:**
- 프로덕션 환경 기본 동작 확인
- 실제 음성 데이터 분석 테스트
- 심각한 버그 즉시 감지

**진행 사항:**
```
├─ 사전 공지 (09:00)
│  └─ 메일 + Slack 알림
├─ 배포 (10:00)
│  └─ 모니터링 24/7
└─ 피드백 수집 (24시간)
   └─ 회사 인트라넷, 메일, 직접 연락
```

**무시할 이슈:**
- UI 미세한 레이아웃 문제
- 성능 최적화 (후속 패치)
- 마이너 기능 미흡

**멈춰야 할 이슈:**
- 로그인 불가
- 데이터 손실
- 음성 업로드 실패
- 미팅 분석 오류

---

#### **2️⃣ Early Access (2일)**
**기간:** 2026-10-02 ~ 2026-10-03

**대상 사용자:** 20명 (부서장 + 활동적 사용자)

**목표:**
- 다양한 업무 시나리오 테스트
- 실제 미팅 데이터 분석 검증
- UX 개선 사항 수집

**배포 방식:**
```
├─ 08:00 조직별 순차 배포
│  ├─ 영업1팀 (5명)
│  ├─ 영업2팀 (5명)
│  ├─ 영업3팀 (5명)
│  └─ 특별 사용자 (5명)
│
├─ 실시간 모니터링
│  └─ 에러율 < 1%, API 응답 < 500ms
│
└─ 저녁 피드백 세션
   └─ 19:00 피드백 미팅
```

**필수 테스트:**
- 아침 미팅 기록 (일반적 시나리오)
- 오후 분석 결과 (즉시 대시보드)
- 저녁 이메일 작성 (Follow-up)

---

## 🔄 자동 롤백 전략

### **자동 롤백 조건**

```
만약 다음 중 하나라도 발생:
✓ 크래시율 > 2% (5분 이상 지속)
✓ API 에러율 > 5% (5분 이상)
✓ 데이터베이스 연결 실패
✓ 로그인 불가
✓ 미팅 분석 실패 > 50%

→ 자동 롤백 실행
→ 관리자에게 즉시 알림
→ 사용자에게 공지
```

### **수동 롤백 프로세스**

```
Phase별 롤백 담당자:
├─ Canary: 개발팀장 + PM (즉시)
├─ Early Access: 부사장 승인 필요 (5분)
└─ GA: CEO 승인 필요 (10분)
```

## 📋 데이터 마이그레이션

### **V1 → V2 데이터 동기화**

#### **마이그레이션 전략**

```
┌─ V1 데이터 (프로덕션) ─┐
│ (사용 중인 레거시)      │
└─────────────────────────┘
           ↓ (읽기)
┌─ 마이그레이션 스크립트 ┐
│ (매시간 실행)          │
└─────────────────────────┘
           ↓ (변환)
┌─ V2 데이터 (신규) ────┐
│ (병행 운영)            │
└─────────────────────────┘
```

#### **마이그레이션 대상**

| 데이터 | V1 → V2 | 시작 | 완료 |
|--------|---------|------|------|
| 사용자 | 복사 (전체) | 2026-10-01 | 2026-10-01 |
| 고객사 | 복사 (전체) | 2026-10-02 | 2026-10-02 |
| 미팅 | 선택적 (최근 3개월) | 2026-10-02 | 2026-10-03 |
| 분석결과 | 새로 생성 | 2026-10-04 | 진행 중 |

#### **마이그레이션 검증**

```sql
-- 1. 데이터 개수 검증
SELECT COUNT(*) FROM v1.users = COUNT(*) FROM v2.users
AND COUNT(*) FROM v1.customers = COUNT(*) FROM v2.customers

-- 2. 데이터 무결성
SELECT * FROM v2.users WHERE email IS NULL OR name IS NULL

-- 3. 성능 검증
EXPLAIN ANALYZE SELECT * FROM v2.meetings ORDER BY created_at DESC
```
