# 녹음 재생 — 계획

- 작성일: 2026-08-12
- 대상 버전: **v2.6.0** (기능 추가)
- 상태: **검증 완료 · 승인 대기**
- 제약: **기존 기능은 변경되지 않는다**

---

## 왜 필요한가

어제 녹취 편집을 넣었다. 그런데 **틀린 것 같아도 원본을 들어볼 수 없다.**
전사 일치도가 64~70% 라 고유명사와 숫자는 자주 틀리는데,
고칠지 말지 판단할 근거가 화면에 없다. 편집 기능이 반쪽인 셈이다.

---

## 조사 결과

### 1. 오디오를 돌려주는 경로가 없다

`UPLOADS.get` 을 쓰는 곳은 `/_probe/r2` 하나뿐이고, 그건 도달 확인용이다.
**저장된 녹음을 들을 방법이 아예 없다.**

### 2. 세그먼트 시각이 파일마다 0으로 돌아간다 ★

실측 — 미팅 `876b8403`(녹음 4개, 세그먼트 404개):

```
#97  : 625초 → 0초
#184 : 609초 → 0초
#313 : 580초 → 1초
최대 시각 10.4분 (실제 미팅은 40분이 넘는다)
```

**원인**: 분석 워크플로가 녹음별 세그먼트를 **시각 보정 없이 이어붙인다.**

```ts
// worker/src/workflows/analysis.ts:181
segments.push({ speaker: s.speaker, start_ms: s.start_ms, end_ms: s.end_ms, text: s.text })
```

각 녹음의 전사는 **그 파일의 0초부터** 시작한다. 이어붙이면 시각이 네 번 처음으로 돌아간다.

### 3. 세그먼트에 출처 녹음이 없다

`transcript_segments` 컬럼:
```
id meeting_id speaker_label speaker_id content start_ms end_ms sort_order
created_at content_original edited_at edited_by highlights
```

**`recording_id` 가 없다.** "이 줄이 어느 파일의 몇 초인지" 를 알 수 없으므로,
줄을 눌러도 무엇을 틀지 정할 수 없다.

### 4. 검증한 것 (계획을 세운 뒤 확인)

| 확인 | 결과 |
|---|---|
| R2 가 Range 를 받나 | **`R2GetOptions.range` 가 `R2Range \| Headers`** — 브라우저 Range 헤더를 그대로 넘길 수 있다 |
| 스트림으로 흘릴 수 있나 | `R2ObjectBody.body` 가 `ReadableStream` — 메모리에 안 올린다 |
| 파일이 얼마나 큰가 | 녹음 42개 · **중앙값 14.7MB** · 최대 24MB · 합계 464MB |

**중앙값이 14.7MB 라 Range 는 선택이 아니다.** 없으면 재생 버튼을 누르고
15MB 를 다 받을 때까지 기다려야 하고, 뒤로 감으면 처음부터 다시 받는다.

## 결정 사항 (사용자 확정)

| 항목 | 결정 |
|---|---|
| 재생 범위 | **녹음별로 나눠 재생.** 오디오를 가공하지 않는다 |
| 서빙 방식 | **Worker 가 중계.** 권한 검사가 들어간다 |
| 이번 범위 | **재생 + 줄 클릭 이동** |

### 왜 녹음별인가

이어붙이려면 오디오를 **가공해 새 파일을 만들어야** 한다 — 코덱·길이·저장 비용이 붙고,
기존 분석 결과의 시각과도 어긋난다. 녹음별로 두면 **지금 있는 시각 데이터를 그대로 쓴다.**

### 왜 서명 URL 이 아닌가

서명 URL 은 **그 주소를 가진 사람은 누구든 들을 수 있다**(만료 전까지).
고객 음성이라 계약서에 적기 까다롭다. Worker 중계는 매 요청에 권한 검사가 들어간다.

## 마이그레이션 `012`

```sql
alter table v2.transcript_segments
  add column if not exists recording_id uuid
    references v2.meeting_recordings(id) on delete set null;

create index if not exists idx_transcript_segments_recording
  on v2.transcript_segments (recording_id)
  where recording_id is not null;
```

**`on delete set null` 인 이유**: 녹음을 지워도 전사는 남아야 한다.
전사문이 분석의 근거이고, 오디오가 없다고 그것까지 지울 이유가 없다.

### 기존 데이터 보정

**할 수 없다.** 이미 저장된 세그먼트는 어느 녹음에서 왔는지 알 방법이 없다 —
`sort_order` 로 추측할 수는 있지만 **틀리면 엉뚱한 오디오를 튼다.**

대신: `recording_id` 가 없는 세그먼트는 **줄을 눌러도 아무 일이 안 일어난다.**
재생기는 뜨고 처음부터 들을 수 있다. 다시 분석하면 채워진다.

> 추측해서 채우지 않는다. "대충 맞는 위치" 는 없는 것보다 나쁘다 —
> 사용자가 그것을 믿고 판단하기 때문이다.

## API 1개

```
GET /recordings/:id/audio
```

- 소유자(또는 관리자)만. 남의 녹음은 404 — 존재 여부도 알리지 않는다
- **Range 요청 지원** — 없으면 브라우저가 전체를 받은 뒤에야 재생을 시작한다.
  40분 녹음이면 수십 MB 를 다 받아야 한다
- `Accept-Ranges: bytes` · `Content-Type` 은 R2 의 것을 그대로

R2 의 `get(key, { range })` 를 쓴다. Worker 는 스트림을 그대로 흘려보낸다 —
메모리에 올리면 128MB 한도에 걸린다.

## 화면

```
┌─ 녹취 ──────────────────────────┐
│ [파트 1/4 ▾]  ▶ ──────○──  12:03 │  ← 재생기
│                                  │
│ 화자A  안녕하세요 …        ▶ 0:15│  ← 줄을 누르면 그 시각으로
│ 화자B  네 반갑습니다 …     ▶ 0:22│
└──────────────────────────────────┘
```

- 녹음이 여러 개면 **고르는 목록**을 둔다
- 줄을 누르면 **그 줄이 속한 녹음**으로 바꾸고 그 시각부터 튼다
- `recording_id` 가 없는 옛 데이터는 **시각 표시도 재생 버튼도 안 보인다**

### 기존 동작과 충돌하지 않게

줄 클릭은 이미 **수정(더블클릭)** 과 **형광펜(드래그)** 이 쓰고 있다.
재생은 **줄 오른쪽의 작은 시각 버튼**(`▶ 0:15`)에만 붙인다 — 본문을 누르는 동작은 그대로다.

## 건드리지 않는 것

- `transcript_segments` 의 기존 컬럼 — `recording_id` 만 추가
- 분석·전사 워크플로의 동작 — **세그먼트 저장에 `recording_id` 를 넣는 한 줄만** 는다
- 녹취 편집·형광펜·재요약·스크롤 동기화 — 그대로
- 기존 엔드포인트 — 전부 새 경로다

---

## 검증

- 마이그레이션을 Docker Postgres 에서 001~012 전체 적용
- **남의 녹음을 못 듣는지** (404)
- **Range 요청이 동작하는지** — `Range: bytes=0-1023` 에 206 과 1024바이트
- 새로 분석한 미팅에 `recording_id` 가 채워지는지
- **옛 세그먼트(recording_id 없음)에서 화면이 깨지지 않는지**
- `tests/012_recording_link.sql` 로 남긴다

## 위험과 대비

| 위험 | 대비 |
|---|---|
| 옛 데이터에서 재생이 엉뚱한 곳을 튼다 | **추측하지 않는다.** `recording_id` 없으면 이동 기능을 감춘다 |
| 큰 파일이 Worker 메모리를 넘긴다 | 스트림을 그대로 흘린다. `arrayBuffer()` 를 쓰지 않는다 |
| Range 미지원으로 재생이 늦다 | Range 를 처음부터 지원한다 |
| 오디오 전송 비용 | R2 는 **송신 요금이 없다**(Cloudflare 내부). Worker 요청 수만 는다 |
| 남의 음성이 새어 나간다 | 매 요청 권한 검사. 서명 URL 을 쓰지 않는 이유다 |

## 하지 않는 것

- 오디오 이어붙이기 — 가공하면 되돌릴 수 없고 기존 시각과 어긋난다
- 옛 세그먼트의 `recording_id` 추측 보정 — 틀리면 엉뚱한 것을 튼다
- 재생 따라 녹취 강조·스크롤 — 미팅노트 스크롤 동기화와 밀 수 있다. 별도 건
- 배속·구간 반복 — 브라우저 기본 재생기에 이미 있다
