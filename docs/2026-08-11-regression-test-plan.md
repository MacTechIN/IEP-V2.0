# 회귀 검증 계획 — 지금까지 고친 것이 아직 고쳐져 있는가

- 작성일: 2026-08-11
- 대상: **v2** (Cloudflare) 중심, v1 은 별도 절
- 상태: **검토 대기.** 승인 후 실행한다

---

## 왜 이 문서가 필요한가

지난 닷새 동안 v2 를 사내 서버에서 Cloudflare 로 옮기면서 **결함 스무 개가량을 고쳤다.**
그 과정에서 두 번, 이미 고친 것이 다시 깨진 것을 나중에야 알았다.

- 미팅 **생성** 경로가 이관 단계 어디에도 없어서, 화면이 Cloudflare 로 넘어온 순간부터
  "업로드 및 분석 시작" 이 전부 404 였다. **누구도 누르기 전까지 아무도 몰랐다**
- `admin@company.com / admin1234` 가 공개 인터넷에서 관리자로 로그인됐다.
  마이그레이션에 "운영 배포 시 반드시 변경" 이라 적혀 있었는데도 그대로 배포됐다

둘 다 **한 번이라도 눌러 봤으면** 즉시 드러났을 것들이다.
이 문서는 "무엇을 눌러 봐야 하는가" 의 목록이다.

### 원칙 세 가지

1. **숫자로 판정한다.** "잘 된다" 가 아니라 요청 수·행 수·바이트로 적는다
2. **고치기 전 코드로도 돌려 본다.** 통과만 하는 검사는 통과하는 법만 아는 검사다
3. **흔적을 남기지 않는다.** 실서비스 DB 를 쓰므로 만든 것은 그 자리에서 지운다

## 2. 권한 — 남의 것이 보이는가

이 절은 전부 **kim 의 토큰으로 jnh 의 자원을 건드려 보는 것**이다.

| # | 무엇이 고장났었나 | 확인 | 통과 기준 |
|---|---|---|---|
| B-1 | 고객 IDOR — ID 만 알면 남의 고객사를 읽고 고쳤다 | `GET·PATCH·DELETE /customers/{남의ID}` | 전부 404 |
| B-2 | 미팅 IDOR — **녹취 전문과 분석 결과가 딸려 나왔다** | `GET /meetings/{남의ID}`, `/analysis/meeting/{남의ID}`, `/…/transcript` | 전부 404 |
| B-3 | 액션 항목에 소유자 범위가 없었다 | `PATCH /actions/{남의ID}` | 404 |
| B-4 | `/admin/users` 가 아예 없었다(404) | kim 토큰 / 토큰 없음 / 관리자 | 403 / 401 / 200 |
| B-5 | 자기 정보 수정으로 role 을 올릴 수 있으면 안 된다 | `PATCH /users/me` 에 `role: "admin"` | 무시됨. role 그대로 |
| B-6 | 관리자 생성 API 가 본문 role 을 그대로 믿으면 안 된다 | `POST /admin/users` 에 `role: "관리자시도"` | `user` 로 저장 |
| B-7 | 남의 고객사에 미팅을 만들 수 있으면 안 된다 | kim 토큰 + jnh 의 `customerId` 로 `POST /meetings` | 404 |
| B-8 | 자기 자신을 비활성화하면 되살릴 사람이 없어질 수 있다 | 자기 ID 로 `PATCH /admin/users/:id {isActive:false}` | 400 |

**B-1·B-2 는 읽기만으로 판정한다.** 예전에 PATCH 로 확인하다 실제 고객 데이터를 건드린 적이 있다.
읽히는 것만으로 이미 결함이므로 쓰기까지 갈 이유가 없다.

## 3. 녹음 유실 — 가장 비싼 결함

2026-08-10 저녁, 세션이 끊긴 상태에서 401 처리기가 `/login` 으로 하드 이동해
**녹음 중이던 미팅이 통째로 사라졌다.** 서버에는 아무것도 도달하지 않았다.

마이크가 없는 환경에서는 합성 오디오를 물린다 — `AudioContext` → `MediaStreamDestination`.
**실제 클릭이 있어야 `AudioContext` 가 깨어난다**(자동재생 정책). 프로그램 클릭으로는 안 된다.

| # | 확인 | 통과 기준 |
|---|---|---|
| C-1 | 녹음 시작 후 15·30초 시점의 IndexedDB | 조각이 **누적**된다 (0 이면 실패) |
| C-2 | 녹음 중 세션을 죽인다(요청 헤더 오염) | **주소가 `/upload` 그대로**, 타이머 계속, refresh 1회 |
| C-3 | 그 상태로 계속 녹음 | 경고 배너 표시, 조각 계속 쌓임 |

| C-5 | 재로그인 후 `/upload` 재방문 | "올라가지 못한 녹음이 N건" + 용량 표시 |

## 5. 실시간 스트림 (Cloud Run)

```bash
cd stream-service && npm run test:stream <PCM파일> <토큰> <URL>
```

입력은 **linear16 모노 16kHz PCM** 이다. 실제 미팅 녹음을 리샘플해 쓴다.

| # | 확인 | 통과 기준 |
|---|---|---|
| E-1 | 주경로 | `engine: deepgram`, 첫 전사 2초 이내, 화자 2명 |
| E-2 | 백업 강제 (`STT_ENGINE=google`) | `engine: google`, `degraded: true`, 전사 나옴 |
| E-3 | 240초 회전 | 417초 오디오로 **오류 없이** 통과 (5분 벽) |
| E-4 | 토큰 없음 / 잘못된 토큰 | 각각 401 |
| E-5 | 허용하지 않은 오리진 | 403 |
| E-6 | 시험 후 | **`STT_ENGINE` 을 반드시 제거**한다 |

E-6 을 빠뜨리면 주경로가 백업으로 고정된 채 남는다. 실제로 한 번 그렇게 뒀다.

## 8. 시험 흔적 정리

실서비스 DB 를 쓰므로 **항목마다 끝나는 즉시** 지운다. 나중에 몰아서 하면 빠뜨린다.

| 만든 것 | 지우는 법 |
|---|---|
| 미팅 | `DELETE /meetings/:id` |
| 고객사 | `DELETE /customers/:id` |
| 녹음 | 화면의 휴지통 아이콘 → `DELETE /recordings/:id` |
| 사용자 | **삭제 API 가 없다.** `PATCH /admin/users/:id {isActive:false}` 로 비활성화 |
| 브라우저 | `localStorage.clear()` · `indexedDB.deleteDatabase('sep-v2-recording-backup')` |

정리 후 `GET /meetings` · `GET /customers` 로 잔존물이 없는지 확인한다.

## 9. 알려진 한계

이 계획으로 **덮이지 않는 것**을 먼저 적는다. 덮인다고 착각하는 편이 위험하다.

- **실제 마이크로는 검증하지 않는다.** 합성 오디오를 `getUserMedia` 에 물린다.
  기기별 코덱·권한 거부·블루투스 전환은 사람이 손으로 봐야 한다
- **화면 회귀는 눈으로 본다.** 스냅샷 테스트가 없다
- **부하는 보지 않는다.** 동시 사용자는 지금 3명이라 의미가 없다
- **사내 Express 백엔드는 대상이 아니다.** 같은 Neon 을 보고 있어 아직 살아 있지만,
  화면은 Cloudflare 만 쓴다. 정리 시점은 별도 논의
- **비밀번호 강도는 검사하지 않는다.** 사용자가 정한 값을 그대로 쓰기로 했다(§B-6 은 role 만 본다)
