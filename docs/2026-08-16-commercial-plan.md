# 상용 버전 개발 계획 — 마이크로 프로세스

> 2026-08-16 작성 · 기준 `v2.7.0` · 마이그레이션 `013`
> 앞선 계획서 `docs/develop_plan.html`(8/12)의 후속. 그 사이에 끝난 것은 빼고, **코드로 다시 확인한 것만** 남겼다.

---

## 0. 이 문서를 어떻게 쓰나

MVP 는 **혼자 또는 소수가 쓰기에 완성**돼 있다. 녹음→전사→분석→보관이 실측으로 끝까지 돈다(08-16).
없는 것은 **여러 조직이 동시에 쓸 때 필요한 것들**이다.

작업 단위는 v1 의 `MICRO_PROCESS.md` 규약을 따른다.

```text
ID:
목표:        한 문장
입력:        시작할 때 이미 있어야 하는 것
작업:        무엇을 만드나
산출물:      파일·마이그레이션·화면
완료 기준:   사람이 화면이나 응답으로 볼 수 있는 것
검증:        실측으로 무엇을 확인하나
막는 것:     이게 없으면 무엇이 안 되나
```

### 운영 원칙

| 원칙 | 왜 |
|---|---|
| **한 단위는 반나절 안에 검증된다** | 더 크면 "거의 다 됐다" 가 길어진다 |
| **완료 기준에 실측값을 넣는다** | "개선했다" 로는 여섯 달 뒤에 아무것도 알 수 없다 |
| **막는 것이 큰 순서로 한다** | 앞이 없으면 뒤가 의미 없는 경우가 많다 |
| **상한은 먼저 재고 나중에 건다** | 지금 얼마나 쓰는지 모르면 상한은 추측이다 |
| **자동으로 지우는 청소기를 만들지 않는다** | 목록을 보여 주고 사람이 정한다 (CLAUDE.md) |
| **마이그레이션에는 검증 SQL 을 함께 낸다** | `database/tests/` 규약 |

### 단계 게이트

각 단계 끝에서 **다음 단계로 갈지 사람이 정한다.** 게이트를 통과하지 못한 항목은
다음 단계로 끌고 가지 않고 그 자리에 남긴다.

## 2. 전체 맵

```text
1단계 — 돈이 새는 것 막기            MP-C01 … C05    약 1주
2단계 — 사람이 늘어도 버티기          MP-C06 … C11    약 1.5주
3단계 — 팔 수 있는 제품              MP-C12 … C18    약 3주
4단계 — 사고를 견디기                MP-C19 … C22    약 0.5주
```

**1단계가 먼저인 이유**: STT 는 20분 오디오당 약 $1.27 이다. 상한이 없으면
버튼을 반복해 누르는 것만으로 비용이 쌓이고, 그건 사용자를 늘리기 전에 닫아야 한다.

```
목표:      새 녹음이 다시 사본으로 넘어간다
입력:      Admin Read & Write 토큰
작업:      CLOUDFLARE_API_TOKEN 재설정 + R2 backup 워크플로에 cron 복구
완료 기준: 새 녹음 1건이 다음 회차에 사본으로 넘어간다
주의:      **Object 범위 토큰은 R2 REST API 가 받지 않는다** (2026-08-15 실측)
```

#### MP-C21 복구 훈련 재개
```
목표:      되돌릴 수 있다는 것을 계속 확인한다
입력:      없음
작업:      Restore drill 워크플로에 cron 복구 (월 1회)
완료 기준: 한 번 돌려 "복구됨" 이 나온다
검증:      테이블 건수·내용 해시 일치
```

#### MP-C22 사내 서버 종료
```
목표:      운영 대상을 하나로 줄인다
입력:      MP-C19 · C20
작업:      사용 흔적 확인 → 컨테이너 정지 → 한 주 관찰 → 폐기
완료 기준: 한 주 동안 아무도 찾지 않는다
주의:      **로그를 먼저 본다.** 2026-08-12 에 종료 직전 실사용이 있었다
```
